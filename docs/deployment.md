# Развёртывание

Сервис рассчитан на личный мини-сервер: один процесс, один пользователь, ни
входящих портов, ни веб-интерфейса. Наружу он только ходит сам — на HLTV и в
Telegram.

## Что нужно на сервере

* Docker с плагином compose (`docker compose version`);
* исходящий доступ к `hltv.org`, `scorebot-lb.hltv.org` и `api.telegram.org` —
  напрямую или через прокси (`HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`/`NO_PROXY`,
  см. «Прокси» в [operations.md](operations.md));
* каталог под данные — несколько мегабайт.

Входящие порты открывать не нужно: бот работает через long-polling
`getUpdates`, а не через webhook.

## Первый запуск на сервере

Исходники на сервере не нужны: образ приезжает из реестра, а от репозитория
требуются два файла.

**1. Каталог и файлы.**

```bash
mkdir -p ~/hltv-notify && cd ~/hltv-notify
curl -O https://raw.githubusercontent.com/v1p3rrr/hltv-notificator/main/compose.yaml
curl -o .env https://raw.githubusercontent.com/v1p3rrr/hltv-notificator/main/.env.example
```

**2. Бот и чат.** Создать бота у [@BotFather](https://t.me/BotFather), забрать
токен. Свой `chat_id` узнать у [@userinfobot](https://t.me/userinfobot) — или
позже спросить у самого бота командой `/whoami`. **Написать боту `/start`**,
иначе он не сможет написать первым.

**3. Заполнить `.env`.** Обязательный минимум — три строки:

```
IMAGE=ваш-логин-docker-hub/hltv-notificator:latest
TELEGRAM_BOT_TOKEN=123456:AA...
TELEGRAM_CHAT_ID=123456789
```

Аккаунтов может быть несколько — тогда id через запятую,
`TELEGRAM_CHAT_ID=123456789,987654321`. Первый в списке основной: в него
садится команда из `TEAM_ID`. Отдельной переменной `TELEGRAM_ALLOWED_CHATS`
больше нет: если она осталась в старом `.env`, перенесите её id сюда.

`IMAGE` зависит от логина Docker Hub, под которым публикует CI. Точное имя
печатает сама сборка: в GitHub Actions открыть последний прогон, раздел
«Опубликовано» — там перечислены все теги и digest.

`DRY_RUN` пока оставить `true`.

**4. Если репозиторий на Docker Hub приватный** — один раз залогиниться:

```bash
docker login
```

**5. Запуск.**

```bash
docker compose pull
docker compose up -d
docker compose logs -f
```

В логах должно появиться примерно это:

```
первая отслеживаемая команда взята из конфига: FORZE Reload (id 12857)
DRY_RUN включён: уведомления пишутся в лог, в Telegram не уходят
сервис запущен: подписчиков 1, команд под наблюдением 1 (FORZE Reload)
GET https://www.hltv.org/team/12857/forze-reload -> 200 за 0.28s
команда 12857 взята под наблюдение: 17 матчей занесены молча
```

**Первый запуск всегда молчаливый**: расписание заносится в базу без
уведомлений, иначе на старте прилетело бы полтора десятка сообщений про уже
сыгранное.

**6. Проверить связь.** Написать боту `/menu` — должно прийти меню с кнопками.

**7. Боевой режим.** Убедившись, что в логах разумное, поставить в `.env`
`DRY_RUN=false` и перезапустить:

```bash
docker compose up -d
```

**8. Настроить под себя** — уже из чата:

```
/track https://www.hltv.org/team/12857/forze-reload
/remind 15m
/tz Europe/Moscow
```

`TEAM_ID` в `.env` нужен только для первого посева, когда список пуст; дальше
команды живут в базе.

## Локальная сборка вместо реестра

На машине с исходниками образ можно собрать самому — для этого есть отдельное
наложение, чтобы на сервере `docker compose up` не пытался собирать:

```bash
docker compose -f compose.yaml -f compose.dev.yaml up -d --build
```

## Обновление

```bash
docker compose pull
docker compose up -d
```

Том с данными при этом не трогается — это важно, см. ниже.

Прибиться к конкретной версии вместо `latest` — переменная `IMAGE` в `.env`:

```
IMAGE=ваш-логин/hltv-notificator:0.1.0-build.42
```

Собрать из исходников — см. «Локальная сборка вместо реестра» выше.

## Данные и бэкап

Каталог `./data` содержит `hltv.db` — там и состояние, и **журнал отправленных
уведомлений**.

**Терять его нельзя.** Без журнала сервис при следующем запуске сочтёт новым
всё, что найдёт, и разошлёт уведомления повторно. Первый запуск на пустой базе
молчаливый, так что катастрофы не будет, но история и счёт по картам пропадут.

```bash
# бэкап на остановленном сервисе
docker compose stop
tar czf hltv-backup-$(date +%F).tar.gz data/
docker compose start
```

База в режиме WAL, поэтому рядом с `hltv.db` лежат `-wal` и `-shm`. Копировать
каталог целиком.

## Публикация образа через CI

Workflow `.github/workflows/ci.yml` собирает и публикует образ на каждый пуш в
`main`. Разделение прав доведено до конца: образ собирается в работе **без
токена** и уезжает дальше архивом, а работа с токеном **не выкачивает
репозиторий вовсе** — она распаковывает готовый архив и толкает слои в реестр.

Что завести в настройках репозитория, чтобы публикация заработала:

| Что | Где | Значение |
|---|---|---|
| `DOCKERHUB_USERNAME` | Settings → Secrets and variables → Actions → **Variables** | логин Docker Hub |
| `DOCKERHUB_TOKEN` | там же → **Secrets**, внутри окружения `dockerhub` | Access Token с правами Read/Write |
| `DOCKERHUB_IMAGE` | **Variables**, опционально | если публикуете в организацию |
| окружение `dockerhub` | Settings → **Environments** | туда кладётся секрет; там же ограничиваются ветки |

Токен — именно Access Token, не пароль, и с правами Read/Write, а не Admin.

Пока переменные не заведены, работы `tests` и `image` проходят, а `publish`
падает с явным сообщением «Не задана переменная DOCKERHUB_USERNAME». Это
заложенная проверка, а не поломка.

### Теги образа

| Событие | Теги |
|---|---|
| пуш в `main` | `<версия>-build.<номер прогона>`, `sha-<коммит>`, `latest` |
| тег `vX.Y.Z` | `X.Y.Z`, `X.Y` |

Версия живёт в `src/hltv_notify/__init__.py`. При выпуске тега CI сверяет его с
этой версией и падает при расхождении: иначе образ с номером 1.2.3 сообщал бы о
себе чужой номер.

Образ подписывается `cosign` без ключей — удостоверение выдаёт сам GitHub на
время шага. Проверить подпись:

```bash
cosign verify <образ>@<digest> --certificate-identity-regexp '.*' --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

## Откат

```bash
IMAGE=ваш-логин/hltv-notificator:sha-<предыдущий коммит> docker compose up -d
```

Схема базы обратно совместима: новые колонки добавляются миграцией при старте,
старые не удаляются. Откат на предыдущую версию образа данные не ломает.

## Запуск без Docker

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
PYTHONPATH=src .venv/bin/python -m hltv_notify
```

Нужен Python 3.10+ (в образе 3.12). Юнит systemd, если нужен, — обычный
`Type=simple` с `Restart=always`, `EnvironmentFile=` и рабочим каталогом
проекта; отдельного файла в репозитории нет, потому что выбран Docker.

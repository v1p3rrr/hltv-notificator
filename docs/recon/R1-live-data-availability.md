# R1 — Есть ли по матчам FORZE Reload живые данные

Дата наблюдения: 2026-08-29. Метод: подключение к scorebot по протоколу из
[R4](R4-scorebot.md) + разбор страниц матчей.

## Проверенные матчи

| Матч | Турнир | Тир | Живой скорборд | Пораундовая история |
|---|---|---|---|---|
| `2396935` Vitality–9z | BLAST Open Porto 2026 | LAN, топ | **да** | **да** |
| `2397229` ex-RUSTEC–Entropy | CCT 2026 Europe Series 8 Closed Qualifier | онлайн-квалификация | **да** | **да** |
| `2397053` Color–**FORZE Reload** | GLuck Moscow Cyber Games 2026 Closed Qualifier | онлайн-квалификация | **да** | **да** |

Ключевая проверка — третья строка: это матч **самой отслеживаемой команды**,
на квалификации, то есть в самом рискованном по ТЗ сценарии. Фид полный.

Показательный фрагмент состояния, снятый с живого матча FORZE (момент
окончания первой карты):

```json

  "live": true, "frozen": true,
  "ctTeamId": 12857, "ctTeamName": "FORZE Reload", "ctTeamScore": 10,
  "tTeamId": 13973,  "tTeamName": "Color",         "tTeamScore": 13,
  "regulationHalfLength": 12, "overtimeHalfLength": 3,
  "ctMatchHistory": { "firstHalf": [12 раундов], "secondHalf": [11 раундов] } }
```

На матче ex-RUSTEC–Entropy пораундовая история пришла в развёрнутом виде, с
типами исходов: `Target_Bombed`, `Target_Saved`, `CTs_Win`, `Terrorists_Win`,
`lost`, каждый с `roundOrdinal` и `survivingPlayers`.

## Выводы

- **E5 и E6 реализуемы.** Живой фид доступен на турнирах того уровня, где
  играет FORZE Reload, а не только на топовых LAN.
- **E6 при этом не следует брать из фида напрямую** — фид не сообщает о конце
  карты (см. ниже). Источником истины по концу карты выбрана страница матча,
  фид даёт ускорение. Подробно — в плане, решение D7.
- Опрос страницы матча остаётся полноценным запасным путём: счёт по картам и
  по половинам виден и на завершённых матчах.

## Важная оговорка про конец карты

В момент окончания карты фид **не** переходит в какое-либо «карта закончена»
состояние: `live` остаётся `true`, а `currentRoundState` уходит в `ended` —
но это состояние **раунда**, а не карты, и оно принимает то же значение в
конце любого обычного раунда. Счёт в фиде — по текущей карте; счёта серии
(по картам) в фиде нет вовсе.

Наивное правило «счёт достиг 13 — карта кончилась» сломается на овертайме и
на нестандартных форматах. Поэтому конец карты детектируется по странице
матча — см. [R3](R3-schedule-source.md), блок про `.mapholder`.

## Граница карт

Механика найдена: в `log` приходит **`{"MatchStarted":{"map":"de_dust2"}}` на
старте каждой карты серии**, а не один раз на матч. Поймано на переходе матча
FORZE со второй карты. Это сигнал для E5 и маркер границы карт.

Остаётся снять полный дамп через границу для replay-тестов —
`fixtures/scorebot-2397053-forze.jsonl.gz`.

## Почему живой фид нужен не только ради E5

Секция карт на странице матча обновляется по половинам и с задержкой (см.
`docs/known-limitations.md`). Значит опрос страницы даёт правильный, но
запоздалый E6. Живой фид знает счёт по раундам в момент их окончания, поэтому
на этапе 4 он становится основным источником скорости, а страница —
подтверждением счёта.
